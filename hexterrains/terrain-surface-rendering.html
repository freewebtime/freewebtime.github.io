    📦 Surface Rendering

    The Hex Terrains Framework supports performant rendering of surface layers (like ground or water) using ECS-compatible systems and highly optimized chunk-based rendering workflows. This section explains how rendering works, what components are involved, and how meshes are dynamically generated and drawn for visible terrain chunks.

    🔁 Rendering Workflow Overview

    Surface rendering is split into three main phases:

    1. Create Render Data The CreateSurfaceRenderDataSystem is responsible for creating a HexSurfaceRenderLayer instance tied to a specific HexSurfaceLayer. This object holds all the render-related data structures including chunk meshes, mesh sources, and render configuration.

    2. Generate Mesh Data The CalcSurfaceMeshesSystem converts the intermediate MeshSource data (generated earlier by procedural or brush-based tools) into actual Unity Mesh objects per chunk. Only dirty or changed chunks are reprocessed.

    3. Render Meshes The RenderHexSurfaceSystem uses Unity’s Graphics.DrawMesh to efficiently render only the visible chunks for the current camera using instancing and render config materials.

    🏗 CreateSurfaceRenderDataSystem

    public class CreateSurfaceRenderDataSystem<TRequest, TSurfaceLayer, TRenderData, TRenderConfig> : SystemBase

    • Purpose: Initializes the render data structure when a TRequest component is present on a terrain entity.

    • Output: Attaches a TRenderData component with:

      • Render settings from the request.
      • Render config asset.
      • Camera reference for rendering.

    • Example Output: Adds HexGroundRenderLayer or HexWaterRenderLayer.

    🧩 Render data includes:

    • ChunkMeshSources (procedural mesh definitions)
    • ChunkMeshes (final Mesh instances)
    • RenderConfig (materials and shadow settings)

    🧬 CalcSurfaceMeshesSystem

    public class CalcSurfaceMeshesSystem<TSurfaceData, TRenderData> : SystemBase

    • Purpose: Builds Unity Mesh objects from procedural MeshSource data for each chunk.

    • Key Features:

      • Skips work if nothing is dirty.
      • Processes only marked dirty chunks via GeneratedMeshIndexes.
      • Fills meshes using MeshSource.FillMesh() and stores them in the render layer.

    • Optimization: Once processed, dirty flags are reset to avoid redundant work.

    🛠 Example:

    meshSources[chunkIndex].FillMesh(chunkMesh);

    【Source: CalcSurfaceMeshesSystem.cs】

    🖼 RenderHexSurfaceSystem

    public class RenderHexSurfaceSystem<TSurfaceData, TRenderData> : SystemBase

    • Purpose: Draws all visible chunk meshes using Graphics.DrawMesh.

    • Features:

      • Uses ChunkVisibility to skip non-visible chunks.
      • Supports view mode switching via HexTerrainViewMode.
      • Can draw multi-material meshes using submesh indices.

    🔍 Pseudocode:

    foreach (chunkIndex in visibleChunks)
    if (chunk is visible)
        DrawMesh(chunkMeshes[chunkIndex], transform, material)
    • Supports: Shadows (IsCastShadows, IsReceiveShadows) and instanced draw calls.

    【Source: RenderHexSurfaceSystem.cs】

    🧾 Supporting Components

    Component / System Purpose
    HexSurfaceRenderLayer Holds all mesh/render data for surface
    MeshSource Procedural mesh buffer (verts, tris, uvs)
    ChunksGridData.ChunkVisibility Visibility status and transform for each chunk
    HexTerrainViewMode View mode index for rendering config
    HexSurfaceRenderConfig Materials, shadow settings, etc.

    ✅ Summary

    The surface rendering pipeline in Hex Terrains Framework is designed for maximum performance and visual clarity, dynamically processing and rendering only the chunks that are visible. The system is highly modular, allowing surfaces like ground and water to be rendered using shared logic, with configuration driven by ECS components and per-layer settings.
