    CellRegionLayer (Regions) — lifecycle, updates, rendering

    This document explains how CellRegionLayer stores “region per cell” data, how it is created/initialized, how derived region data is rebuilt, and how the per-cell ColorMap is copied into Texture2D instances during a frame.

    1) What CellRegionLayer is

    CellRegionLayer (file: Runtime/Regions/Data/CellRegionLayer.cs) is a HexTerrainLayer responsible for:

    • Storing one integer region id per cell (CellRegionMap)
    • Building derived structures for region queries:
      • RegionCells: region id → list of cell indices in that region
      • RegionSizes: region id → number of cells in that region
    • Producing a per-cell color buffer (CellRegionMap.ColorMap) that can be copied to a Texture2D for UI/material usage

    Core data layers

    Field Type Meaning
    CellRegionMap ColorMapCellValueDataLayer_Int The authoritative “region id per cell” map (+ an associated ColorMap)
    RegionCells NativeParallelMultiHashMapDataLayer<int, uint> Built from CellRegionMap when it changes
    RegionSizes NativeListDataLayer<uint> Built from CellRegionMap when it changes (length is set to 255)

    2) “CellRegion is simply an integer value per cell”

    CellRegionMap stores an int per cell index.

    • Cell index: linear index in [0 .. CellsCount-1]
    • Cell value: region id (int)
      • Expected to be non-negative

    Dirty tracking (why updates are cheap)

    All these data layers are chunked (derive from ChunkedDataLayer). When you set one cell value, only the cell’s chunk (and sometimes neighbors if the cell sits on a chunk edge) is marked dirty.

    Key behavior (from ChunkedDataLayer / NativeListChunkedDataLayer):

    • TrySetData(index, value) → SetData(index, value) → SetCellDirty(index, checkEdges: true)
    • SetCellDirty(...):
      • marks the chunk dirty in ChunkDirtyGrid
      • adds chunk index to DirtyChunks
      • calls SetDirty(true) on the layer

    This is what makes per-frame recalculation scalable: jobs can skip cells whose chunks aren’t dirty.

    3) Initialization: how a CellRegionLayer is created and initialized

    There are two layers of “ownership”:

    1. The layer instance: CellRegionLayer
    2. The group component attached to the terrain ECS entity: CellRegionLayerGroup

    3.1 CellRegionLayerGroup (what it is)

    CellRegionLayerGroup (file: Runtime/Regions/Data/CellRegionLayerGroup.cs) is:

    • a managed ECS component: class CellRegionLayerGroup : HexTerrainLayerGroup<CellRegionLayer>, IComponentData
    • a container for multiple CellRegionLayer instances

    This is the standard pattern in this framework: a group component is attached to a terrain entity, and it contains one or more managed layer instances.

    3.2 CreateCellRegionLayerGroupRequest → layer creation

    CreateCellRegionLayerGroupRequest (file: Runtime/Regions/Data/CreateCellRegionLayerGroupRequest.cs) is a buffer element that can create a layer:

    • It holds:
      • Name (FixedString128Bytes)
      • Args (UnityObjectRef<CellRegionLayerConfigAsset>)
    • CreateTerrainLayer() calls config.CreateTerrainLayer() which returns new CellRegionLayer().

    3.3 CellRegionLayerConfigAsset (how init parameters are authored)

    CellRegionLayerConfigAsset (file: Runtime/Regions/Data/CellRegionLayerConfigAsset.cs) provides:

    • InitValuesArgs of type InitColorMapCellValueDataLayerArgs<int>
      • initial fill options (fill constant/random/from texture)
      • min/max values (used by some color modes)
      • AutoColorMapMode
      • ColorPalette (list of Color32)
    • AutoFillColorPalette() helper (editor context menu)
      • uses AutoColorMapSettings to generate a palette sized for MaxValue

    3.4 Group hooks that actually initialize the layer

    CellRegionLayerGroup overrides two important methods:

    • CreateTerrainLayer<TInitArgs>(initArgs)
      • creates the layer (usually via factory)
      • sets layer.Name from the request
    • InitTerrainLayer<TInitArgs>(layer, settings, initArgs)
      • calls layer.Init(settings, request.Args.Value) if the init args match

    3.5 CellRegionLayer.Init(...): what gets allocated and configured

    CellRegionLayer.Init(HexTerrainSettings settings) allocates/initializes:

    • CellRegionMap → Init(settings.CellsCount, settings)
    • RegionCells → Init(settings.CellsCount, Allocator.Persistent)
    • RegionSizes → Init(255, Allocator.Persistent)
    • then base.Init(settings) which updates Settings and may mark dirty on resize

    CellRegionLayer.Init(settings, ICellRegionConfig args) then applies config:

    • InitColoredDataLayer(CellRegionMap, args.InitValuesArgs)

    That call delegates to the extension ColorMapCellValueDataLayer<T>.InitColoredDataLayer(args) which:

    • applies fill options (IsFillWithValue, IsFillWithRandomValues, IsApplySourceTexture)
    • sets AutoColorMapMode, MinValue, MaxValue when the layer supports auto color mapping
    • initializes the ColorPalette
    • marks all chunks dirty

    4) Updating values at runtime

    4.1 Writing values

    Primary API:

    • SetCellRegion(int cellIndex, int regionIndex)
      • calls CellRegionMap.TrySetData(cellIndex, regionIndex)
      • this marks the affected chunk(s) dirty

    Bulk API:

    • SetAllCellsRegion(int regionIndex)
      • fills the entire map
      • marks all chunks dirty

    Read API:

    • GetCellRegion(int cellIndex) returns int?

    4.2 Rebuilding derived region data

    When region ids change, you often need:

    • CalcRegionsCells(dependency)
      Builds RegionCells (region → cells list)
    • CalcRegionsSizes(dependency)
      Builds RegionSizes (region → count)

    Both methods bail out unless CellRegionMap.IsDirty == true.

    CalcRegionsCells(...) job

    • Clears RegionCells
    • Schedules CalcRegionsCellsJob (IJobParallelFor):
      • reads CellValuesMap[index] (region id)
      • does SortedValues.Add(regionId, (uint)index)

    CalcRegionsSizes(...) job

    • Ensures RegionSizes length is 255
    • Resets all entries to 0
    • Schedules CalcRegionsSizesJob (IJob):
      • loops through all cells
      • increments RegionSizes[regionId]

    Important constraint:

    • CalcRegionsSizesJob assumes region ids are valid indices (non-negative). In practice, keep region ids >= 0.

    5) How the integer region id becomes a cell color

    CellRegionMap is ColorMapCellValueDataLayer_Int, which derives from:

    • AutoColorMapCellValueDataLayer<int> → ColorMapCellValueDataLayer<int>
    • and owns:
      • the values (NativeList<int> Data)
      • the colors (ColorMapDataLayer ColorMap), which is a CellColorsDataLayer + a ColorPalette

    5.1 Color calculation modes

    AutoColorMapCellValueDataLayer<T>.CalculateColorMap(dependency) chooses a mode:

    • GradientThroughPalette
    • ColorIndexByValue
    • Custom

    For region visualization, the typical choice is:

    • AutoColorMapMode.ColorIndexByValue

    5.2 ColorIndexByValue: palette lookup

    ColorMapCellValueDataLayer_Int.CalculateColorMap_ColorIndexByValue(...) schedules GetCellValueColorsFromPaletteJob_Int:

    • For each cell index:
      • skips work if the cell’s chunk is not dirty (ChunkDirtyGrid)
      • value = CellValues[index] (region id)
      • if 0 <= value < ColorPalette.Length: Color = ColorPalette[value]
      • else Color = DefaultColor (default is transparent)

    Result: CellRegionMap.ColorMap.Data[index] becomes the final per-cell color.

    6) How ColorMap is copied to a Texture2D

    The actual CPU → Texture2D copy happens in CellColorsDataLayer.ApplyColorsToTexture(Texture2D texture):

    1. CompleteAllJobs()
      Ensures any scheduled color calculation jobs are finished before reading ColorMap.Data.

    2. Ensure texture size matches terrain size
      If texture.width/height != Settings.TerrainSize.x/y:

      • texture.Reinitialize(width, height, TextureFormat.RGBA32, mipmaps: false) (defaults)

    3. Upload pixels + apply

      • texture.SetPixelData(ColorMap.Data.AsArray(), 0)
      • texture.Apply()

    So the Texture2D ends up containing a 2D image where each pixel corresponds to one terrain cell.

    7) What happens during a frame (render-side path)

    The system that performs the per-frame texture update is:

    • UpdateColorMapTexturesSystem (file: Runtime/Systems/UpdateColorMapTexturesSystem.cs)
    • runs in HexTerrainsRenderGroup (presentation phase)

    7.1 System call chain

    UpdateColorMapTexturesSystem.OnUpdate() does:

    • Query terrains with:
      • HexTerrain, HexTerrainViewMode, HexTerrainVisibility, ViewModeCollectionConfigComponent
      • excluding NotInitializedTerrain
    • If not visible → returns
    • Loads the current view-mode config from ViewModeCollectionConfigAsset
    • Computes isViewModeDirty if the HexTerrainViewMode component changed since last frame
    • Calls:
      • viewModeConfig.UpdateColorMap(EntityManager, terrainEntity, isViewModeDirty)

    7.2 View-mode config decides which map(s) are copied

    ViewModeConfigAssetBase provides helpers for pulling layers from ECS:

    • GetTerrainLayer<TLayerComponent, TLayer>(...)
      • uses entityManager.TryGetComponentObject<TLayerComponent>(terrainEntity, out layerComponent)
      • then layerComponent.GetLayer<TLayer>(layerReference)

    Two common view-mode config implementations:

    • ViewModeConfigAsset (texture list driven)
    • UniversalViewModeConfigAsset (explicit list of “items” each with a texture)

    For regions, UniversalViewModeConfigAsset uses:

    • GetTerrainLayer<CellRegionLayerGroup, CellRegionLayer>(...)
    • then returns cellRegionLayer.CellRegionMap?.ColorMap

    7.3 The final “copy if dirty” condition

    All view-mode implementations ultimately call:

    • ViewModeConfigAssetBase.UpdateColorMapTexture(CellColorsDataLayer colorMap, bool isViewModeDirty, Texture2D texture)

    It copies only if:

    • colorMap.IsDirty == true or isViewModeDirty == true

    And the copy itself is:

    • colorMap.ApplyColorsToTexture(texture)

    8) Cleanup and disposal

    8.1 Cleanup() (per-frame dirty reset)

    CellRegionLayer.Cleanup() calls:

    • CellRegionMap.Cleanup()
    • RegionSizes.Cleanup()
    • RegionCells.Cleanup()

    Most layers implement cleanup at the beginning of frame by clearing dirty chunk flags when IsDirty is true, so it is possible to cheaply detect new changes down the frame.

    There is also:

    • CleanupAsync(dependency) which schedules the “clear dirty flags” work as jobs and combines dependencies.

    8.2 Dispose() (free persistent memory)

    CellRegionLayer.Dispose() disposes:

    • CellRegionMap (includes its ColorMap + palette)
    • RegionCells
    • RegionSizes

    CellColorsDataLayer.ApplyColorsToTexture() and CellRegionLayer.SerializeLayer() both call CompleteAllJobs() to ensure no jobs are still using disposed native memory.

    9) Serialization

    CellRegionLayer supports ISerializableTerrainLayer:

    • SerializeLayer(BinaryWriter writer)
      • CompleteAllJobs()
      • serializes CellRegionMap (values)
    • DeserializeLayer(BinaryReader reader, HexTerrainSettings terrainSettings)
      • CompleteAllJobs()
      • Init(terrainSettings) to ensure correct sizing
      • deserializes CellRegionMap
      • SetAllDirty(true) to force refresh (including ColorMap recalculation + texture copy)

    10) Summary diagram (frame flow)

    flowchart TD 
A["Gameplay/editor code modifies regions (SetCellRegion / SetAllCellsRegion)"] --> B["CellRegionMap marks chunks dirty (ChunkDirtyGrid + DirtyChunks)"] 
B --> C["Optional: CalcRegionsCells / CalcRegionsSizes rebuild derived region data"] 
B --> D["CellRegionMap.CalculateColorMap schedules jobs (palette lookup or gradient)"] 
D --> E["Presentation: UpdateColorMapTexturesSystem calls viewModeConfig.UpdateColorMap(...)"] 
E --> F["ViewModeConfig chooses CellRegionMap.ColorMap and target Texture2D"] 
F --> G["CellColorsDataLayer.ApplyColorsToTexture completes jobs, SetPixelData, Apply"]

    Practical notes / gotchas

    • Region id range matters

      • For palette-based coloring (ColorIndexByValue), region ids should be valid palette indices.
      • For RegionSizes indexing, keep region ids non-negative and within [0..InitValuesArgs.MaxValue]

    • Texture size is terrain size

      • The target Texture2D is reinitialized to Settings.TerrainSize if needed.

    • Color calculation is separate from texture copy

      • The render system copies ColorMap → Texture2D.
      • The ColorMap itself must be calculated (typically via CellRegionLayer.CalculateColorMap(...) / CellRegionMap.CalculateColorMap(...) in your update pipeline). The copy step will block until jobs complete, but it won’t invent colors if you never schedule the calculation.
