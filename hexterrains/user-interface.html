    🧩 UI Binding System in Hex Terrains Framework

    The UI in Hex Terrains Framework is built on Unity UI Toolkit and uses a data-driven binding system that seamlessly synchronizes UI screens with underlying runtime data.

    This system ensures UI elements always reflect the current application state, and allows runtime tools (like terrain brushes, minimaps, and tool selectors) to respond to user input with minimal boilerplate.

    🧱 Core Concepts

    Component Role
    UIDataSource Base class for all bindable data. Tracks changes using a Version.
    IViewDataReceiver<T> Interface for screens to receive and apply data sources.
    UIScreen<T> Base class for all UI screens, supports binding and updating.
    ToolSettingsScreen<T> Generic base for tool-specific UI panels.
    MinimapScreenBase Base for minimap UI, receives view data updates from systems.

    📊 Data Binding with UIDataSource

    All data exposed to UI inherits from UIDataSource. This abstract class handles:

    • Change detection via a Version counter
    • Dirty tracking using MarkDirty()
    • UI invalidation with CommitChanges()
    public abstract class UIDataSource : ICommitChanges {
    public long Version;

    public virtual void MarkDirty() => Version++;
    public virtual void CommitChanges() => MarkDirty();
}

    When a value changes, CommitChanges() increments the Version, signaling UI Toolkit to rebind affected elements.

    🔁 View Data Lifecycle

    1. A screen receives a data object via SetViewData(T viewData)
    2. The screen assigns the data to its root visual element's .dataSource
    3. UI Toolkit auto-binds fields based on [CreateProperty] attributes
    public virtual void SetViewData(TSettings viewData) {
    _viewData = viewData;
    if (TryGetRootElement(out var rootElement)) {
        rootElement.dataSource = viewData;
    }
}

    This flow is defined in ToolSettingsScreen<T> and reused across all UI panels.

    🧰 Example: Tool Settings Panel

    public class UniversalToolSettingsScreen : ToolSettingsScreen<UserToolSettingsDataSource> { }
    • Binds to UserToolSettingsDataSource, which is a UIDataSource
    • Automatically reflects settings like brush size, tool parameters, and visibility
    • Changes to settings (e.g., via sliders or dropdowns) update the bound data and propagate to the active user tool

    🗺️ Example: Minimap UI

    The minimap UI is backed by MinimapScreenDataSource, a subclass of UIDataSource.

    Key properties:

    [CreateProperty] public List<Texture2D> ColorMapTextures;
[CreateProperty] public List<DisplayStyle> ColorMapTextureVisibilities;
[CreateProperty] public Vector2 CameraNormalizedPosition;

    When SetColorTextures(...) or SetViewMode(...) is called in MinimapScreenBase, it updates the data source and commits changes:

    ViewData.SetVisibleTextureIndexes(visibleIndexes);
ViewData.CommitChanges();

    This triggers an immediate UI refresh showing the correct textures and view modes.

    🧪 UI Message Routing (Optional)

    The IViewDataReceiver<T> and base IViewDataReceiver interfaces support message routing and generalized UI communication.

    ✅ Benefits

    • Declarative, low-code UI architecture
    • Automatic UI refresh on data changes
    • Clean separation between logic and presentation
    • Highly extensible and testable

    🧱 UI Toolkit Custom Controls and Data Templates

    In addition to core screen and data binding infrastructure, the Hex Terrains Framework includes a powerful set of custom UI Toolkit components to streamline data-driven UI development.

    These components support dynamic layout, list rendering, event handling, and runtime template selection.

    🔘 UIButton: Unified Button Binding

    The UIButton component enhances Unity's standard Button by supporting multiple binding strategies for click handling:

    [CreateProperty]
public object OnClick { get; set; }

[CreateProperty]
public string OnClickPath { get; set; }

    Supported click targets include:

    • Action
    • UnityEvent
    • UIButtonDataSource (with an OnClick action)
    • Property path bindings (using OnClickPath)

    This flexibility allows UI to invoke methods on view models or data sources declaratively.

    📃 SimpleListView: Static Template Lists

    The SimpleListView displays a list of items using a single VisualTreeAsset template:

    [CreateProperty]
public VisualTreeAsset ItemTemplate { get; set; }

[CreateProperty]
public IList itemsSource { get; set; }

    For each item in itemsSource:

    • A view is instantiated using ItemTemplate
    • Its .dataSource is assigned
    • If the view implements ICommitChanges, it is refreshed automatically

    This is ideal for simple collections with consistent UI layout.

    🧩 UIListView: Event-Driven Selection

    UIListView extends Unity’s native ListView with enhanced selection binding. You can assign:

    • UnityEvent<IEnumerable<object>>
    • UnityEvent<int>
    • Action<int> or Action<IEnumerable<object>>

    All are invoked automatically when the user changes selection.

    public object OnSelectionChange { get; set; }

    🎭 Template Selection System

    The framework supports data-driven UI templates using:

    • TemplateSelectorConfig: Base for defining default templates
    • TemplateSelectorConfigByType: Maps C# types to specific templates
    • DataTemplateConfig: Stores the mapping between type and VisualTreeAsset

    This system allows runtime UI to render heterogeneous data models with distinct views based on data type.

    public override VisualTreeAsset GetTemplateForData<TData>(TData data) {
    return GetTemplateForType(typeof(TData));
}

    🧱 TemplateSelectorElement: Dynamic UI Rendering

    TemplateSelectorElement dynamically selects and instantiates a view template at runtime based on the data it is bound to.

    How it works:

    1. Retrieves a data object from the UI hierarchy using GetHierarchicalDataSourceContext
    2. Selects a template via a TemplateSelectorConfig
    3. Creates and binds a view using the selected template
    4. Automatically updates when data changes or when reattached to panel

    This mechanism is ideal for modular and polymorphic UIs such as:

    • Properties panels for different object types
    • Inspector-style interfaces
    • Minimap overlays with customizable visuals

    Component Purpose

    SimpleListView Fast list rendering using one template
    UIListView Flexible list view with event-driven selection
