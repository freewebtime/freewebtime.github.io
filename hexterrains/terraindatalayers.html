    🧩 Hex Terrain DataLayers

    Purpose

    Each terrain entity in the Hex Terrains Framework is made of one or more TerrainLayers, and each TerrainLayer encapsulates one or more DataLayers that store specific simulation or rendering data for the terrain.

    These DataLayers are organized into:

    • Per-cell layers – storing data for each terrain cell (like biome, height, color)
    • Per-chunk layers – storing data per chunk (like visibility or mesh sources)

    📋 Built-in DataLayers

    Below is a catalog of the key built-in DataLayers provided by the framework, organized by their type and role.

    ▶️ Per-Cell Layers

    Data Layer Class Description Data Type Chunked Disposable Notes
    CellBiomesDataLayer Stores biome index per cell byte ✅ ❌ Biome classification
    CellColorsDataLayer Stores Color32 per cell Color32 ✅ ❌ Can be exported to texture
    CellMetricsDataLayer Stores detailed cell info (e.g., world position, height) HexCellMetrics ✅ ❌ Also maintains a NativeList<float3> of cell positions
    HeightMapDataLayer Stores height data per cell byte ✅ ❌ Scaled by HexTerrainSettings.HeightScale

    📦 Per-Chunk Layers

    Data Layer Class Description Data Type Chunked Disposable Notes
    ChunkMeshesDataLayer Stores Mesh objects for each terrain chunk Mesh ✅ ✅ Disposes meshes with .SmartDestroy()
    ChunkMeshSourcesDataLayer Stores raw mesh source data MeshSource ✅ ✅ Contains GeneratedMeshIndexes list
    ChunkMetricsDataLayer Stores performance and structure metrics HexChunkMetrics ✅ ❌ One entry per chunk
    ChunkVisibilityDataLayer Tracks visibility status of terrain chunks ChunkVisibility ✅ ❌ Maintains multiple visibility sets (e.g. NewVisibleChunks)

    ⚙️ HexTerrainDataLayer Specialization

    All custom terrain layers derive from either:

    • HexTerrainNativeListChunkedDataLayer<T> — for native container backed layers
    • HexTerrainListChunkedDataLayer<T> — for managed list-based layers

    These abstract base classes inject terrain-aware settings:

    • Grid sizes (TerrainSize, ChunksGridSize)
    • Chunk sizes (ChunkSize)
    • Wrapping options (IsConnectedHorizontally, IsConnectedVertically)
    public override int2 CellsGridSize => Settings.TerrainSize;
public override int2 ChunkGridSize => Settings.ChunksGridSize;
public override int2 ChunkSize => Settings.ChunkSize;

    Initialization

    Each layer implements a custom Init(int layerSize, HexTerrainSettings settings) that must be called during terrain layer setup.

    🧼 Cleanup Pattern

    Each DataLayer defines:

    • Cleanup() — synchronous cleanup called each frame or update cycle
    • CleanupAsync() — job-based version for use in systems that schedule updates

    These methods typically reset dirty flags or clear visibility sets:

    public override void Cleanup()
{
    SetAllChunksDirty(false);
}

    For visibility layers:

    public override JobHandle CleanupAsync()
{
    var handle1 = NewVisibleChunks.ClearNativeParallelHashSetAsync(dependency);
    var handle2 = VisibleChunks.ClearNativeParallelHashSetAsync(dependency);
    return JobHandle.CombineDependencies(handle1, handle2);
}

    🔓 Examples

    Example: Applying Color to Texture

    public void ApplyColorsToTexture(Texture2D texture)
{
    CompleteAllJobs();
    if (texture.width != Settings.TerrainSize.x)
        texture.Reinitialize(Settings.TerrainSize.x, Settings.TerrainSize.y);
    Data.AsArray().CopyTo(_cellColors);
    texture.SetPixels32(_cellColors);
    texture.Apply();
}

    Example: Initializing Cell Metrics

    public override void Init(int layerSize, HexTerrainSettings settings)
{
    base.Init(layerSize, settings);
    if (!CellPositions.IsCreated)
        CellPositions = new NativeList<float3>(Allocator.Persistent);
    CellPositions.SetItemsCount(layerSize);
}
