    Terrain Serialization and Deserialization

    📦 HexTerrainSerializer

    The HexTerrainSerializer is a static utility class that provides serialization and deserialization functionality for HexTerrain entities in the framework. It is used to persist terrain state to disk and restore it later. This is especially useful for save/load systems, debugging, world editors, or network transfers.

    It supports:

    • Versioning for backward compatibility
    • Standard and custom component serialization
    • Flexible stream or file-based operations

    ✨ Features

    • Serializes terrain settings and selected managed components.
    • Supports custom serialization logic via user-provided callbacks.
    • Backward-compatible versioning system for future-proofing saved data.
    • Works entirely with ECS-friendly components and native containers.

    💾 Saving Terrain

    SaveTerrainToFile

    public static bool SaveTerrainToFile(string filePath, Entity terrainEntity, EntityManager entityManager, CustomSerializerCallback customSerializer)
    • Saves the terrain to a specified file.
    • Internally calls Serialize.

    🔄 Serialization

    There are three main overloads for serialization:

    Serialize(Stream stream, Entity terrainEntity, EntityManager entityManager, CustomSerializerCallback customSerializer)

    Serialize(BinaryWriter writer, Entity terrainEntity, EntityManager entityManager, CustomSerializerCallback customSerializer)

    WriteVersion1(BinaryWriter writer, Entity terrainEntity, EntityManager entityManager, CustomSerializerCallback customSerializer)

    • Writes the current version number.

    • Writes terrain settings using WriteTerrainSettings.

    • Enumerates all managed components and serializes recognized types:

      • HexSurfaceLayer
      • CellItemsLayer
      • CellEntitiesLayer
      • HexByteAreasLayer

    • Supports custom serialization logic by invoking the CustomSerializerCallback.

    Supported Layer Writers:
    • WriteSurfaceData
    • WriteCellItemsData
    • WriteCellEntitiesData
    • WriteTerrainByteAreas
    Component Type Resolution
    TypeHash.CalculateStableTypeHash(componentType.GetManagedType())

    Used to store the component type in a format that’s stable and consistent.

    📂 Deserialization

    LoadTerrainFromFile

    public static bool LoadTerrainFromFile(string filePath, Entity terrainEntity, EntityManager entityManager, CustomDeserializerCallback customDeserializer)

    Loads terrain data from a file and applies it to the target terrain entity.

    🔓 Deserialization Methods

    Deserialize(Stream stream, ...)

    Deserialize(BinaryReader reader, ...)

    ReadVersion1(BinaryReader reader, ...)

    • Reads and applies the terrain settings.

    • Matches type hashes to existing component types.

    • Deserializes data into existing component objects using:

      • ReadSurfaceData
      • ReadCellItemsData
      • ReadCellEntitiesData
      • ReadTerrainByteAreas

    🧩 Supported Layers

    The following managed components are supported out of the box:

    Component Type Write Method Read Method
    HexSurfaceLayer WriteSurfaceData ReadSurfaceData
    CellItemsLayer WriteCellItemsData ReadCellItemsData
    CellEntitiesLayer WriteCellEntitiesData ReadCellEntitiesData
    HexByteAreasLayer WriteTerrainByteAreas ReadTerrainByteAreas

    🧪 Custom Serialization

    CustomSerializerCallback

    public delegate bool CustomSerializerCallback(BinaryWriter writer, object componentObject);

    Called during write if the user wants to handle custom logic.

    CustomDeserializerCallback

    public delegate bool CustomDeserializerCallback(BinaryReader reader, Type componentType, HexTerrainSettings terrainSettings);

    Called during read if the user wants to deserialize custom logic.

    📘 Usage Example

    HexTerrainSerializer.SaveTerrainToFile("Assets/terrain.bin", terrainEntity, entityManager, MyCustomSerialize);
HexTerrainSerializer.LoadTerrainFromFile("Assets/terrain.bin", terrainEntity, entityManager, MyCustomDeserialize);

    🧱 Binary Format Summary

    1. Terrain format version (int)
    2. HexTerrainSettings struct (int2, floats, enums)
    3. Component Type Hash (ulong)
    4. Native list data (length + binary contents)

    ✅ Best Practices

    • Always complete all jobs (CompleteAllJobs) before saving to ensure consistency.
    • Keep serialization layer-specific logic in their respective data layers.
    • Use the custom serializer to support user-defined or experimental components.
