    🖌️ In-Game Terrain Editor

    Overview

    The Hex Terrains Framework features a powerful in-game terrain editor designed with a Photoshop-like workflow in mind. It supports:

    • Brush-based editing with size, opacity, and color control
    • Modular tools for deforming terrain, painting areas, placing objects, and more
    • A runtime state machine to manage tools
    • Full UI Toolkit integration via a shared UI system
    • Clean separation between UI code and ECS-based terrain data

    🎛️ User Tool System Architecture

    Each editor tool is a state within a UserToolStateMachine, allowing seamless switching between editing modes.

    Key Components

    Component Description
    UserToolStateMachine Runtime state machine managing tool transitions
    UserToolStateBase Base class for all tool states; handles activation, brush setup, view mode
    IHexTerrainAPI Interface injected into tools to access terrain editing APIs
    UserToolSettings Data-driven brush/tool parameters
    IUISystemAPI UI integration layer for editor panels and toolbars

    🔁 Tool Lifecycle

    Each tool derives from UserToolStateBase and can optionally:

    • Initialize a UI panel (ShowSettingsScreen)
    • Activate a custom brush with settings
    • Switch terrain view modes
    • Apply edits using ApplyBrush(...)

    Example Lifecycle Flow

    [Tool Selected]
     ↓
PrepareToRun()
     ↓
Set View Mode / Show Brush
     ↓
Tick() – per-frame updates
     ↓
ApplyBrush(...) – on user input
     ↓
PrepareToStop() – restore view mode, hide UI

    🖼️ Tool Example: Deform Ground

    Class: DeformGroundUserToolState

    This tool deforms terrain height based on mouse input, key modifiers, and brush size.

    public class DeformGroundUserToolState : DeformHeightUserToolState<HexGroundLayer>
{
    public override int UserToolType => (int)UserToolTypes.GroundDeformation;
}

    Modifier Keys

    Key Effect
    LeftAlt Inverts height delta
    LeftShift Applies turbo strength

    🗺️ Tool Example: Paint Countries

    Class: PaintCountriesUserToolState

    This tool paints area indices (such as countries) onto cells, optionally constrained by elevation.

    public class PaintCountriesUserToolState : PaintAreasUserToolState<HexCountriesLayer, HexGroundLayer>
{
    public override int UserToolType => (int)UserToolTypes.CountriesPainting;
}

    Settings

    • Index – area index (byte 0–255)
    • Min Cell Height – skip cells below this elevation
    • Max Cell Height – skip cells above this elevation

    🧠 IHexTerrainAPI – Bridging Tools and Terrain

    The IHexTerrainAPI allows tools to interact with terrain layers outside ECS systems:

    public interface IHexTerrainAPI
{
    void SetIsVisibleBrush(bool isVisible);
    void SetBrushSize(int size);
    void SetBrushColor(Color32 color);
    void SetIsResizableBrush(bool isResizable);
    int GetViewMode();
    void SetViewMode(byte mode);
    byte GetCellHeight<TSurfaceLayer>(int cellIndex) where TSurfaceLayer : HexSurfaceLayer;
    // ... other helper methods
}

    This ensures tools are lightweight, testable, and do not manipulate ECS state directly.

    🧩 Creating a New Tool

    To implement a new terrain editing tool:

    1. Inherit from UserToolStateBase or a derived class like BrushUserToolState
    2. Implement ApplyBrush(...) with your editing logic
    3. Set a unique UserToolType ID
    4. Register the tool in your state machine
    5. (Optional) Provide a UI panel by calling ShowSettingsScreen

    Template

    public class MyCustomToolState : BrushUserToolState<SomeLayer>
{
    public override int UserToolType => (int)UserToolTypes.MyTool;

    public MyCustomToolState(IHexTerrainAPI hexTerrainAPI) : base(hexTerrainAPI) { }

    public override bool ApplyBrush(...)
    {
        // Custom logic here
    }
}

    📐 Brushes & Cursors

    Brush visuals and interaction are controlled via IHexTerrainAPI:

    • Size
    • Color
    • Opacity
    • Visibility
    • Resizability

    All brush properties are dynamically adjusted based on tool and user input.

    🧠 Tool Settings UI

    Tools can define custom settings through data-driven UserToolSettingsDataSource:

    DataSource.AddValue(new UserToolParameterDataSource<int>
{
    Name = "Min Cell Height",
    MinValue = 0,
    MaxValue = 255,
    Value = 3,
    IsClampValue = true,
    IsVisible = true
});

    The UI system automatically binds these parameters to in-game panels using a common UIScreen and IViewDataReceiver.

    🧼 Cleanup and Memory Safety

    All tools implement:

    • Dispose() for cleanup
    • PrepareToStart() to prepare tool for work and show UI
    • Tick() to apply per-frame logic
    • PrepareToStop() to revert view modes and hide UI and more (see UserToolStateBase)

    🖌 Brush-Based Terrain Editing

    The BrushUserTool system powers the in-game Photoshop-like editing experience within the Hex Terrains Framework. It allows real-time, cell-level modifications of terrain layers using a dynamic, customizable brush. Each tool is implemented as a state in a user tool state machine and inherits from a shared foundation: BrushUserToolState.

    Key Features

    • Adjustable brush size and opacity
    • Unified API for diverse operations (e.g., painting countries, applying heightmaps, stamping objects)
    • Tool-specific logic via overrideable brush application methods
    • Data-driven settings exposed via UI
    • Supports undo/redo, smooth user interactions, and multi-step operations

    🔧 Base Class: BrushUserToolState

    The core abstract base class:

    BrushUserToolState<TBrushTarget, TDataSource, TUIScreen>
    • TBrushTarget: The layer type affected (e.g., HexSurfaceLayer, CellEntitiesLayer)
    • TDataSource: A class describing editable settings (usually UserToolSettingsDataSource)
    • TUIScreen: The settings panel (usually UniversalToolSettingsScreen)

    Example Implementations

    Tool Inherits From Purpose
    ApplyHeightmapUserToolState BrushUserToolState<HexSurfaceLayer, ...> Paints heightmap values onto terrain cells
    AutoPaintUserToolState BrushUserToolState<HexSurfaceLayer, ...> Auto-assigns biomes based on elevation
    PaintCountriesUserToolState PaintAreasUserToolState<HexCountriesLayer, ...> Assigns country indices per cell
    LevelTerrainUserToolState BrushUserToolState<HexSurfaceLayer, ...> Sets cells to a specific elevation
    StampUserToolStateBase BrushUserToolState<...> Copies cell data from one area to another

    🔁 Brush Lifecycle

    Each frame while a brush is active:

    1. Cursor location is evaluated (HexTerrainAPI.GetCellCoordUnderCursor()).
    2. Affected cells within brush radius are gathered.
    3. ApplyBrush(...) is invoked for each cell.
    4. Layer-specific logic (e.g., biome assignment, height change, object stamping) is applied.
    5. UI settings are updated if necessary (e.g., when reading a value).

    🧠 User-Defined Parameters

    Each brush tool can expose user-facing parameters:

    DataSource.AddValue(new UserToolParameterDataSource<int> {
    Name = "Elevation",
    Value = 0,
    MinValue = 0,
    MaxValue = 255,
    IsVisible = true,
});

    These parameters are shown in the editor UI and persisted during the session.

    ✍️ Overriding ApplyBrush

    Every brush tool must override ApplyBrush:

    public override bool ApplyBrush(int brushMode, int2 cellCoord, int cellIndex, TBrushTarget target, int mouseButton)

    For example, in ApplyHeightmapUserToolState, the method reads a value from a texture and updates the terrain height:

    var pixel = Heightmap.GetPixelBilinear(progress.x, progress.y);
var height = (byte)math.clamp(pixel.r * scale * 255 + offset, 0, 255);
brushTarget.SetCellHeight(cellIndex, height);

    🧬 Extending BrushUserTool

    To create a custom brush tool:

    1. Inherit from BrushUserToolState<TBrushTarget, TDataSource, TUIScreen>
    2. Override InitDefaultSettings() to register UI parameters.
    3. Override ApplyBrush(...) with logic for applying edits.
    4. Register your tool in the state machine (UserToolStateMachine.SwitchStateByUserToolType(...)).

    🛠️ HexTerrainAPI: Default Implementation of IHexTerrainAPI

    The HexTerrainAPI class is the default implementation of the IHexTerrainAPI interface, designed to bridge runtime user tools (e.g., brush operations) with ECS-based HexTerrain data structures.

    It provides a standardized way for tool states to interact with terrain data, access brush settings, UI screens, and read/write values from data layers such as heightmaps, biomes, cell entities, and areas — all without requiring direct access to the EntityManager.

    🔑 Purpose

    • Acts as a facade over the EntityManager, abstracting terrain access logic.

    • Enables tools (like BrushUserToolState) to:

      • Modify terrain data (e.g., deform terrain, paint biomes).
      • Read/write brush settings (size, opacity, visibility).
      • Manage terrain lifecycle (create, destroy, resize, save/load).
      • Interact with UI (via injected IUISystemAPI).

    • Is injectable into tool states as IHexTerrainAPI.

    🔧 Core Components

    Property Description
    EntityManager ECS context for terrain access.
    TerrainEntity Current active terrain entity.
    UserToolEntity Tool controller entity (provides prefab configs, settings).
    UISystemAPI Interface to manage UI screens (create, destroy, retrieve).

int? GetCellIndexUnderCursor()
int2? GetCellCoordUnderCursor()
