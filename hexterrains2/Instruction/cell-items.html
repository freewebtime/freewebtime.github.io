    📦 CellItems System

    Overview

    The CellItems system enables the placement of static props, decorations, or visual objects directly onto terrain cells. These can include trees, rocks, buildings, or any custom object defined by the user. Each cell can contain a single CellItem, which refers to a configuration entry (a prefab, mesh, or rendering instruction), making it extremely memory-efficient and suitable for large terrains.

    CellItems are rendered using a RenderEntities system rather than traditional ECS entities, enabling better performance and scalability.

    🧱 Key Components

    CellItemsLayer

    • Stores the actual cell-level data — which item is placed in which cell.

    • Inherits from HexTerrainLayer.

    • Contains:

      • CellItems: A NativeArrayDataLayer<CellItem> — the main item assignment per cell.
      • ItemConfigs: A buffer of configuration structs (CellItemConfig) referencing assets, meshes, materials, and other rendering metadata.
      • RenderEntities: A NativeParallelMultiHashMapDataLayer<RenderEntityKey, RenderEntity> — acts as the bridge to the rendering system by collecting render commands.

    CellItemPropsLayer

    • A parallel system used for procedural or runtime cell item generation.
    • Used for randomizing terrain props during creation using CreateCellPropsDataRequest.

    🏗️ Creation Flow

    CreateCellPropsDataSystem

    • Runs under the CreateHexTerrainsGroup.

    • When a CreateCellPropsDataRequest is present on a HexTerrain entity, this system:

      1. Creates a new CellItemPropsLayer.
      2. Initializes it using the terrain's settings and item configuration buffer.
      3. Optionally fills the terrain with randomized props (based on height or range).
      4. Removes the request component once processing is complete.

    CreateCellPropsDataRequest

    • Contains parameters such as:

      • IsFillWithRandomData: whether to auto-generate.
      • MinCellHeight, MaxCellHeight: filters.
      • MinRandomPropIndex, MaxRandomPropIndex: range of prop types.
      • ColorMapTextureIndex: for visualizing cell item distributions.

    🔄 Runtime Updates

    CalcCellItemsSystem

    • Runs continuously to compute visible render instructions from cell item data.

    • Only recalculates when:

      • Cell items, metrics, or chunk visibility are marked dirty.

    • Combines read/write dependencies to ensure thread-safe access.

    • Main responsibilities:

      • Clears existing render entries.
      • Schedules a CalcCellItemsJob to generate new render entries.

    CalcCellItemsJob

    • Iterates over all visible chunks and creates a list of RenderEntity descriptors based on:

      • Cell height.
      • Item configuration (e.g., meshes, materials, transforms).

    • Populates RenderEntities with these descriptors for fast rendering.

    🧹 Cleanup

    CleanupCellPropsDataSystem

    • Clears cell item dirty flags

    🔧 Authoring & Config

    Authoring Components

    • CellItemsLayerAuthoring: attaches the initial layer on authoring.
    • CellItemPrefabAuthoring: defines asset references for each CellItemConfig.

    🖼️ Rendering Notes

    • Rendering is handled via RenderEntities, not ECS entities.
    • This allows thousands of items to be rendered with extremely low CPU overhead.
    • Each RenderEntity contains: mesh, material, submesh index, and a transform matrix.

    🚀 Benefits

    • Highly optimized for large-scale terrains.
    • Jobified and multithreaded with tight memory management.
    • Customizable and extensible: new item types, conditional placements, dynamic updates.

    📦 Cell Items System

    The Cell Items System allows you to place and manage static, non-entity objects in hexagonal terrain cells—ideal for populating the terrain with props such as trees, rocks, decorations, and similar elements. It is designed for performance and scalability using a non-entity rendering pipeline via Graphics.DrawMeshInstanced.

    🔧 Configuration

    Each cell can contain a CellItem, which stores:

    • An index into a shared array of CellItemConfig, defining mesh, material, and behavior.
    • A state index, allowing visual or logical variation per configuration (e.g., seasonal variants, damaged states).

    These are authored using:

    • CellItemConfigAuthoring.cs: defines mesh/material combinations and transform data.
    • CellItemPrefabAuthoring.cs: creates CellItemConfig assets.
    • CellItemsLayerAuthoring.cs: places item instances on the map during terrain authoring.

    📐 Simulation Workflow

    Simulation systems compute visibility and transform for each cell item, producing renderable data.

    1. System Setup:

      • Systems like CreateCellPropsDataSystem and CleanupCellPropsDataSystem manage lifetime of supporting data.
      • CalcCellItemsSystem populates and updates the CellItem data for each terrain cell.

    2. Job Execution:

      • CalcCellItemsJob is a Burst-compiled job that runs in parallel for every visible terrain cell.

      • It:

        • Skips cells outside the view frustum (ChunkVisibility).
        • Looks up the CellItemConfig and relevant state.
        • Computes local-to-world transform using chunk + cell + item transforms.
        • Emits RenderEntity instances into a NativeParallelMultiHashMap<RenderEntitySettings, RenderEntity>.
    public partial struct CalcCellItemsJob : IJobParallelFor
{
    public void Execute(int index)
    {
        var chunkIndex = Settings.GetChunkIndexByCellIndex(index);
        if (!ChunkVisibilityGrid[chunkIndex].IsVisible) return;

        var cellItem = CellItems[index];
        var itemConfig = ItemConfigs[cellItem.Index];
        var cellMetrics = CellMetrics[index];

        var itemStateConfig = itemConfig.GetStateConfig(cellItem.State);
        var chunkTransform = ChunkVisibilityGrid[chunkIndex].Transform;
        var cellTransform = cellMetrics.CellTransform_Local;

        foreach (var reSettings in itemStateConfig.RenderEntities)
        {
            var transform = chunkTransform * cellTransform * baseTransform;
            RenderEntities.Add(reSettings, new RenderEntity { Settings = reSettings, Transform = transform });
        }
    }
}

    1. Color Mapping:

      • CalcCellItemsColorsSystem computes cell item color overlays used in the minimap and terrain editor via CalcCellItemColorsJob.

    🎨 Rendering Pipeline

    Unlike entities rendered by Unity's Hybrid Renderer, Cell Items are drawn manually via instancing using Graphics.DrawMeshInstanced, which enables:

    • Lower overhead than GameObjects or Entities.
    • Efficient frustum culling via chunk visibility.
    • Support for up to 8 submeshes per item.

    Key Rendering Types:

    • RenderEntity:

    Final Step:

    • SortRenderEntitiesJob batches and groups render entities by RenderEntitySettings for efficient draw calls.
    • The final draw submission happens in rendering systems downstream RenderCellItemsDataSystem:
    public virtual void UpdateItems(in HexTerrainVisibility terrainVisibility, CellItemsLayer itemsData, Camera camera)
{
	if (!terrainVisibility.Value)
	{
		return;
	}

	var renderEntitiesConfig = itemsData.RenderEntitiesConfig;
	var renderEntities = itemsData.RenderEntities;
	var cellItems = itemsData.CellItems;

	if (cellItems == null || renderEntitiesConfig == null)
	{
		return;
	}

	cellItems.OpenToRead();

	if (!renderEntities.IsCreated || renderEntities.IsEmpty)
	{
		return;
	}

	var worldBounds = new Bounds(Vector3.zero, Vector3.one * 100000f);

	renderEntitiesConfig.RenderEntities(renderEntities, camera, worldBounds);
}

    You can easily:

    • Add more item types by creating new CellItemConfig assets.
    • Extend rendering behavior by customizing RenderEntitySettings.
    • Add interaction or visibility logic by plugging into the chunk visibility grid or extending render utility systems.
